# Trip Recorder NG

Неофициальный регистратор поездок для автомобилей BYD с головным устройством DiLink. Он записывает каждую поездку на
самом головном устройстве (маршрут, скорость, расход батареи и энергии, топливо, сессии зарядки, стоимость) и показывает
записанное на экранах, повторяющих штатное приложение BYD «Driving behavior»: «Эта поездка», «Мои поездки», «Достижения»,
«Статистика», «Зарядка» и «Твики», а также страницы «Вопросы и ответы» и «Настройки». Всё остаётся в автомобиле,
ничего не выгружается. Приложение работает на английском, арабском (с раскладкой справа налево) и русском языках.

Пакет `org.triprecorderng`. Собрано и проверено на одном подключаемом гибриде с DiLink 5.1 (Android 13). Другие модели BYD
и версии ПО могут вести себя иначе; сообщения об ошибках и исправления приветствуются.

> **Не связано с BYD.** «BYD» и «DiLink» принадлежат их владельцам и используются здесь лишь затем, чтобы сказать, с чем
> работает приложение. Перед установкой прочитайте [Отказ от ответственности](#отказ-от-ответственности).

## Зачем это нужно
Собственный регистратор поездок BYD, часть приложения My Car («Driving behavior»), зависит от сервера BYD. BYD ввела на этом
сервере географические ограничения, поэтому в затронутых регионах регистратор больше не работает.

Trip Recorder NG закрывает этот пробел. Он записывает такие же данные прямо на головном устройстве, хранит всё в автомобиле
и не требует ни сервера BYD, ни учётной записи BYD, поэтому географическое ограничение не может его отключить.

## Быстрый старт
1. Соберите APK командой `./build.sh` (см. [Сборка](#сборка)).
2. Установите его на головное устройство через ADB: `adb install -r --user 0 TripRecorderNG.apk` (нужен доступ по ADB к
   головному устройству; как его включить, зависит от модели и версии ПО; о `--user 0` см. [Установка / обновление](#установка--обновление)).
3. Откройте приложение и разрешите доступ к местоположению.
4. В настройках автомобиля Setting > BYD auto-start apps («Disable background Apps») выключите переключатель
   **Trip Recorder NG** (выключено = запуск разрешён), затем один раз перезагрузите головное устройство. Без этого BYD не даёт
   приложению запускаться самостоятельно. Этот переключатель сбрасывается при **каждой** установке или обновлении
   (см. [Установка / обновление](#установка--обновление)).
5. Необязательно, но рекомендуется: включите Настройки > Канал данных автомобиля, чтобы получать данные о батарее, энергии,
   одометре, топливе и зарядке (см. [Канал данных автомобиля](#канал-данных-автомобиля-необязателен-по-умолчанию-выкл)).
   Приложение также спрашивает об этом при первом открытии после установки или обновления и снова через неделю, пока канал выключен.

## Отказ от ответственности
- Это неофициальный любительский проект, предоставляемый «как есть», без каких-либо гарантий (см. [LICENSE](LICENSE)). Вы
  устанавливаете и используете его на свой страх и риск. BYD его не одобряет и не поддерживает.
- Он читает данные автомобиля через внутренний недокументированный API автомобиля BYD. Любое обновление ПО автомобиля может
  изменить или сломать его. Единственное, что приложение меняет в автомобиле, — это переключатель передачи данных в роуминге
  Android, запрос на подключение к облаку BYD, переключатель AVAS (внешнего звука электромобиля) и перезагрузка модема, когда вы
  нажимаете кнопку или включаете переключатель на вкладке «Твики»; при включённых **Камерах слепых зон** оно также выдаёт
  себе разрешение на камеру и на отображение поверх других приложений и, только с параметром для приборной панели, ставит флаг
  автомобиля для показа окна на приборной панели, пока это окно открыто; а ещё — само приложение, когда вы выбираете
  «Установить» после «Проверить обновления» (оно заменяет себя сборкой, загруженной из релизов этого проекта на GitHub и
  подписанной тем же ключом).
- Необязательный **Канал данных автомобиля** запускает небольшого помощника через собственную службу отладки головного
  устройства на 127.0.0.1 (ADB через loopback) с ключом, который приложение создаёт само. На проверенном устройстве автомобиль
  принял этот ключ без запроса, а значит, любое приложение на этом устройстве могло бы сделать то же самое; это свойство
  автомобиля, а не этого приложения. Оставьте канал выключенным, если вас это не устраивает. Выключение останавливает
  помощника, а **Забыть** удаляет ключ.
- Не пользуйтесь экраном за рулём. Приложение записывает само и не требует внимания на дороге.

## Конфиденциальность
Поездки хранятся в собственной базе данных приложения на головном устройстве. Резервные копии и экспорт (JSON, CSV, GPX)
записываются в `Documents/TripRecorderNG` — общую папку, которую может читать любое приложение с доступом к хранилищу. Они
содержат GPS-треки, то есть показывают, где вы живёте и ездите: удалите их или не делитесь ими, если это важно для вас.
Приложение запрашивает разрешение INTERNET для loopback-соединений с помощником и службой отладки автомобиля, а также для
**Настройки > Проверить обновления**. Само по себе приложение в сеть не выходит и ничего не выгружает. К GitHub
(`api.github.com`, а для загрузки сборки — `github.com`) оно обращается, только когда вы нажимаете «Проверить обновления» или
«Установить»; GitHub при этом видит IP-адрес автомобиля и название сборки приложения. Открытие поездки в картографическом
приложении (сведения о поездке) передаёт поездку тому приложению, которое вы выберете.

## Что делает приложение
- Служба переднего плана запускается при загрузке и записывает поездки локально (SQLite). Ничего не выгружается.
- Источник данных выбирается автоматически (см. `VehicleProvider`):
  1. API автомобиля BYD, вызываемый напрямую, 2. binder `autoservice`, вызываемый напрямую,
  3. помощник с правами пользователя shell (только когда включён Настройки > Канал данных автомобиля, см. ниже),
  4. **только GPS** (запасной вариант; поездки тогда определяются по движению).
  Автомобиль отказывает обычному приложению в 1 и 2 (`SecurityException: permission deny`): для этих показаний нужны
  разрешения BYD `BYDAUTO_*_GET` уровня подписи, которые могут иметь только системные приложения.
- В режиме «только GPS» записываются: скорость, расстояние, длительность, маршрут (GPS-трек), максимальная и средняя скорость,
  резкие разгоны и торможения и простая оценка вождения. Поездка начинается после 3 с выше 5 км/ч и заканчивается после
  3 минут стоянки; поездки короче 50 м отбрасываются.
- Недоступно в режиме «только GPS»: состояние зажигания, заряд батареи в %, счётчик энергии, одометр
  (в этих столбцах показывается «--»).
- Экспорт: CSV (все поездки) и GPX (по поездке) в Documents/TripRecorderNG.
- Сведения о поездке: касание трека открывает список **Открыть трек в** с установленными в автомобиле картографическими
  приложениями (`MapLink`, `TrackProvider`):
  - Приложения, открывающие файлы GPX, например OsmAnd, получают поездку как файл GPX и рисуют **точный трек**, включая
    участки вне дорог. Этим вариантом стоит пользоваться, когда маршрут уходил с дорог.
  - Google Карты, Яндекс и 2GIS не умеют открывать GPX или рисовать произвольную линию по ссылке, поэтому получают поездку как
    маршрут для автомобиля (начало, конец и до 8 промежуточных точек формы). Между этими точками они едут по дорогам, поэтому
    список помечает их «Строится по дорогам, а не по точному треку» (поездка в 186 км показала 207 км в Картах), и им нужен
    интернет в автомобиле.
  - «Другие приложения» передаёт файл GPX в собственный выбор приложений Android (файловые менеджеры и другие просмотрщики GPX).
  Список строится из того, что установлено; файл GPX — это временная копия в кэше приложения, и её может прочитать только
  выбранное вами приложение.

## Эта поездка
Левая карточка показывает, что автомобиль делает сейчас: состояние записи, шкалу, которая показывает заряд батареи, пока
автомобиль стоит или заряжается, и скорость, пока он едет, а также состояние GPS и данных автомобиля. Заметка под ней
говорит, что исправить, когда BYD блокирует автозапуск или «Канал данных автомобиля» выключен (нажмите на неё, чтобы открыть
«Настройки»). Правая карточка — текущая поездка или последняя: расстояние, время в пути и оценка вождения, затем скорость,
энергия и поведение, а внизу — сколько поездка израсходовала на данный момент (электричество в кВт·ч, топливо в литрах) и
сколько она стоила; у поездки, в которой сжигалось топливо, расход всей поездки на 100 км показан под кВт·ч и литрами.
Плитка энергии показывает оставшийся и использованный заряд батареи и расход: кВт·ч/100 км и насколько он отличается от
медианы ваших предыдущих полностью электрических поездок или, когда двигатель вёз автомобиль 5 км и более, две цифры,
описанные в разделе [Расход в гибридной поездке](#расход-в-гибридной-поездке). Нажмите на карточку, чтобы открыть сведения
о поездке. Исходный код: `ThisTripPage`, `GaugeView`.

## Вождение и стоянка
Поездка длится, пока включено зажигание, поэтому автомобиль, оставленный на стоянке с включённым кондиционером или с
подключённым кабелем, остаётся в той же поездке часами. Приложение отделяет езду от стоянки в каждой поездке: стоянка от
5 минут и дольше считается парковкой, а более короткие остановки (перекрёстки, пробки) — частью езды. То, что автомобиль
израсходовал на стоянке, показано как **На стоянке** в сведениях о поездке и не входит в кВт·ч/100 км нигде (Эта поездка, Мои
поездки, сведения, Статистика, Достижения, советы по вождению); время стоянки не входит во время в пути, самое долгое
вождение и общее время в пути. Итоги поездки (кВт·ч, литры, батарея, стоимость) по-прежнему включают всё. Разделение делается
по записанным замерам по ходу поездки и один раз — для поездок, записанных до его появления или восстановленных из резервной
копии; поездка без сохранённых замеров остаётся с полными значениями. В экспорте CSV есть время и энергия езды и стоянки.
Исходный код: `DriveSplit`, `Trip`.

## Расход в гибридной поездке
Счётчик энергии автомобиля показывает чистое значение: он уменьшается и тогда, когда двигатель заряжает батарею и когда
автомобиль рекуперирует энергию, поэтому одна цифра кВт·ч/100 км для поездки, в которой работал двигатель, вводит в
заблуждение (бензиновые километры считаются бесплатными). Поэтому поездка, в которой двигатель работал 5 км и более,
показывается двумя цифрами, разделёнными по собственным счётчикам электрических и гибридных километров автомобиля:
- **Электро**: кВт·ч на 100 км, пройденных на электричестве. Энергия, которую двигатель закачал в батарею, прибавляется к
  израсходованным кВт·ч (она оценивается по росту уровня заряда во время движения, по кВт·ч на пункт заряда, измеренному в
  этой же поездке), чтобы зарядка от двигателя не улучшала вид электрической езды.
- **Гибрид**: литры на 100 км, пройденных при работающем двигателе. Включает топливо, которое зарядило батарею.

Обе цифры — оценки. «Электро» показывает «--», когда на электричестве пройдено меньше 5 км или заряд за время езды упал
меньше чем на 8 пунктов; «Гибрид» требует 5 км гибридной езды. Поездка, в которой двигатель работал меньше, показывается
как электрическая. Итоги (кВт·ч, литры, стоимость) остаются точными, и простые цифры тоже на месте: сколько вся поездка
израсходовала на 100 км, включая стоянку (под итогами на «Эта поездка» и в блоке «Расход» сведений). В «Статистике» «Расход» —
это чистые кВт·ч на 100 км каждой поездки, а «Электро» не включает поездки, в которых сжигалось топливо; «Топливо» — это
израсходованные литры, а «Л/100 км» — литры на 100 км гибридной езды. В «Достижениях» «Мин. расход» — это самое низкое чистое
значение среди всех поездок и, во второй строке, среди поездок без топлива, а «Расход топлива» — литры на 100 км гибридной
езды. Исходный код: `TripEnergy`, `EnergyLoader`, `Stats`.

## Мои поездки и зарядка
Оба списка группируют строки по дням: карточка на день с датой и итогами дня (поездки, расстояние и стоимость; или сессии,
набранный заряд и добавленная энергия) и строками дня внутри, под подписями столбцов, показанными один раз над списком. В
шапке «Мои поездки» есть «Экспорт CSV». В сведениях о поездке «Экспорт GPX» и «Удалить» находятся в строке заголовка; в сведениях
о сессии зарядки там же «Показать место» и «Удалить». Исходный код: `MyTripsPage`, `ChargingPage`, `TripDetailPage`,
`ChargeDetailPage`.

## Резервное копирование и восстановление
Каждая завершённая поездка и сессия зарядки дополнительно записывается небольшим файлом JSON (сводка, трек, события, замеры
батареи и энергии) в `Documents/TripRecorderNG/backup`, поэтому они переживают удаление приложения или очистку его данных. В
«Настройках» есть «Автоматическое резервное копирование» (включено по умолчанию), «Сделать копию сейчас» и «Восстановить из
резервной копии» (добавляет недостающее, ничего не перезаписывает; удаление поездки или сессии в приложении удаляет и её
файл резервной копии). «Мои поездки» предлагают кнопку восстановления, когда список пуст, а файлы резервных копий есть.
Исходный код: `Backup`.

## Сведения о поездке
Маршрут, окрашенный по скорости (зелёный — медленно, красный — 130+ км/ч), красные и янтарные точки для резкого торможения и
разгона, а под картой — график «Скорость», «Батарея», «Высота» или «Эффективность» (кВт·ч/100 км по диапазонам скорости).
Касание графика отмечает этот момент на карте. Для «Батареи», «Эффективности» и точек событий нужны данные, записанные этой
версией (у более старых поездок есть скорость и высота). Исходный код: `RouteView`, `TripChartView`, `TripChartsPanel`,
`TripAnalysis`.

## Когда поездка заканчивается
Поездка, начатая по зажиганию, заканчивается, когда зажигание читается как выключенное (5 с отсрочки). Если состояние
зажигания прочитать нельзя (помощник канала данных не работает и остался только GPS), поездка не закрывается по правилу
стоянки, а удерживается открытой: она заканчивается, только если зажигание оставалось нечитаемым 10 минут и автомобиль стоял
3 минуты, и её временем окончания тогда считается последний момент, когда зажигание было включено или автомобиль двигался. По
этому правилу она никогда не заканчивается, пока автомобиль движется, а 10 минут без каких-либо данных о скорости всё равно
её завершают. Поездка, начатая по движению (без зажигания), заканчивается после 3 минут стоянки, как и раньше. Правила
находятся в `TripEnd`; проверено на автомобиле выключением канала данных на 5 минут на стоянке: поездка осталась открытой и
продолжилась, когда канал вернулся. Отдельно: открытая поездка возобновляется, если приложение перезапустилось в течение
10 минут (поэтому перезапуск не разрезает поездку).

## Стоянка на месте
Пока автомобиль стоит, точка (скорость 0, батарея, положение) всё равно сохраняется каждые 10 с (3 с во время движения),
поэтому на графиках скорости, батареи и высоты нет дыр на остановках. Без GPS-сигнала и при стоящем автомобиле (гараж)
используется последнее известное положение. Для поездок, записанных до этого изменения, график скорости рисует разрыв плоской
линией, когда обе стороны не выше 5 км/ч (настоящая дыра в данных на скорости по-прежнему рвёт линию), а графики батареи и
высоты соединяются через разрывы. Движение пальцем по графику двигает курсор вместе с пальцем и показывает значения,
интерполированные между замерами, в том числе через участок без замеров; через настоящую дыру в данных (линия разорвана)
курсор привязывается к ближайшему замеру. График эффективности игнорирует замеры, когда автомобиль стоял. Исходный код:
`RecorderService`, `TripAnalysis`, `TripChartView`.

GPS-положение стоящего автомобиля «гуляет» на десятки метров, и долгая стоянка нарисовала бы из этого каракули. Поэтому замеры,
сделанные, пока скорость автомобиля меньше 1 км/ч, сохраняют положение (и высоту) последнего замера в движении, когда поездка
показывается или экспортируется (`TripAnalysis.holdStill`; сохранённые точки не меняются, так что и более старые поездки
приводятся в порядок). Поездка, в которой автомобиль так и не тронулся, показывает одну точку и «Автомобиль не двигался»;
карта никогда не приближается меньше чем до 65 м.

## Расстояние поездки
Расстояние поездки читается из собственного счётчика поездки автомобиля (пробег поездки на приборной панели,
`BYDAutoInstrumentDevice.getCurrentJourneyDriveMileage`, шаг 0,1 км, через помощника) и складывается шаг за шагом, так что
сброс счётчика учитывается. Оно совпало с одометром и GPS-путём на проверенной поездке (35.5 / 35 / 35.49 км). Регистратор
также интегрирует показание спидометра, которое примерно на 4 % выше настоящей скорости (37.0 км для той же поездки); этот
интеграл (`speed_km`) используется только до 1 км, когда показаний счётчика ещё нет, и для оценки участка, пройденного до
первого чтения счётчика. Долгая поездка уточняет сохранённое отношение (начинается с 0.958). GPS используется для маршрута, а
не для расстояния. Исходный код: `JourneyTracker`. Если две сессии зарядки идут одна за другой при одном уровне заряда и без
поездки между ними (с разницей до 12 ч), они объединяются в одну (`ChargeRecorder.repairSplits`).

## Зарядка
Нужен «Канал данных автомобиля»: помощник читает `BYDAutoChargingDevice` (только геттеры). Сессия начинается, когда состояние
управления батареей — «зарядка» (1, или 13 — пауза) при подключённом кабеле, и заканчивается через минуту после того, как оно
прекращается; по пути замеряется заряд батареи в %. На проверенном устройстве автомобиль сообщает состояние и тип кабеля
(AC/DC), но мощность зарядки и заряженные кВт·ч читаются как 0, поэтому показанная энергия — оценка: набранные % × кВт·ч на %,
выученные по поездкам (медиана поездок с расходом не менее 8 %; здесь 0.32 кВт·ч/%). Если устройство сообщает кВт·ч, берётся
это значение.
Головное устройство засыпает, когда автомобиль выключен, и во сне приложение не работает. Сессия, начало которой приложение
не видело, или с пропуском в показаниях 2.5 минуты и более, помечается как *Неполная*; когда сессия заканчивается, уровень
заряда в этот момент становится её итоговым уровнем (более низкое показание, как при отъезде автомобиля, игнорируется).
Неполные сессии не показывают среднюю мощность.
Если устройство проспало всю зарядку (автомобиль выключили, подключили к зарядке, зарядили, затем включили), приложение
сохраняет последний увиденный уровень заряда (на постоянной основе) и сравнивает его с уровнем при пробуждении: рост на 2 %
и более при признаке зарядки (кабель подключён или есть состояние зарядки) или на 5 % и более без него записывается как
сессия «только окно» (уровни до и после, времена — это окно, а не длительность зарядки). Меньший скачок без признака зарядки
считается перекалибровкой батареи и игнорируется. Исходный код: `ChargeRecorder`, `Charge`, протокол помощника v2 (`chg`).

## Функции штатного приложения Driving behavior
Этот автомобиль — подключаемый гибрид: помимо батареи автомобиль сообщает счётчик топлива (литры), счётчики расстояния в
режимах EV и HEV, уровень топлива и оставшийся запас хода на электричестве и на топливе. Каждая поездка теперь записывает
счётчики топлива и EV/HEV так же, как счётчик энергии (протокол помощника v3, БД v5), а «Эта поездка» показывает, сколько
поездка израсходовала на данный момент (электричество в кВт·ч, топливо в литрах) и сколько она стоила. У поездок до этого
обновления данных о топливе нет.
- **Калькулятор стоимости** (Настройки > Цены на энергию: электричество за кВт·ч, топливо за литр, валюта; значения по
  умолчанию — 0.010 OMR/кВт·ч и 0.239 OMR/л, местные цены автора, они используются для любой цены, которую вы оставите
  пустой, чтобы стоимость считалась всегда: укажите там свою валюту и свои цены). Стоимость поездки = израсходованная
  энергия × цена электричества + израсходованное топливо × цена топлива; она показывается в каждой поездке, в итоге «Мои
  поездки», как график «Стоимость» в «Статистике» (по дням и месяцам) и в CSV. Сессиям зарядки стоимость считается по
  добавленной энергии. Потери при зарядке не учитываются. `Cost`, `Prefs`.
- **Сведения о поездке**: стоимость поездки вверху, блок «Расход» (электрическая и гибридная цифры, зарядка от двигателя, вся
  поездка на 100 км, стоимость на 100 км), израсходованное топливо, электрическое и гибридное расстояние, время простоя,
  время выше 100 км/ч и «Советы по вождению» (тексты советов штатного приложения, выбираемые простыми правилами). `Advice`.
- **Достижения**: уровень вождения и путь до следующего (названия уровней как в штатном приложении, шаг по записанным
  километрам), рекорды (самая длинная поездка и самое долгое вождение, максимальная скорость, самая экономичная поездка и
  самая экономичная чисто электрическая поездка, лучший расход топлива при гибридной езде, лучшая оценка вождения) и итоги
  (поездки, время в пути, стоимость, израсходованное топливо, расход топлива, избежанный CO2: оценка относительно бензинового
  автомобиля с 8 л/100 км, за вычетом сожжённого топлива и 0.4 кг CO2 на кВт·ч).
- Переключатель **Записывать маршрут** (в штатном приложении «Historical track»): выключен = новые поездки не сохраняют ни
  маршрут, ни положения событий.
- Невозможно офлайн: национальные и городские рейтинги штатного приложения и названия мест (они приходят с сервера BYD). Не
  сделано: оценка по ремню безопасности, кондиционеру, указателям поворота и сигналам смены полосы.

## Напоминание об автозапуске
Собственный переключатель BYD («Disable background Apps») прочитать нельзя, поэтому приложение выводит его состояние: если
системное широковещательное сообщение о запуске не дошло до приложения после последней перезагрузки, автозапуск заблокирован;
сразу после установки или обновления он «ещё не подтверждён» (BYD тогда сбрасывает переключатель). В обоих случаях диалог
объясняет, как выключить переключатель, и предлагает **Открыть настройки BYD**. Он показывается **при каждом открытии
приложения**: новом запуске приложения или возвращении после того, как экран был в стороне дольше 3 секунд (смена языка или
диалог не считаются новым открытием, а после того как вы перешли из напоминания на экран BYD, оно ждёт 10 минут). Он не
показывается, пока автомобиль движется, и в первые 3 минуты после загрузки (сообщение о запуске могло ещё не дойти), и
прекращается сам, как только перезагрузка запустила приложение.
- **Больше не показывать** отключает его, но напоминание всё равно возвращается при каждом 15-м открытии приложения, пока
  автозапуск заблокирован (открытия считаются с момента, когда вы отключили напоминание; диалог напоминания тогда предлагает
  **Показывать каждый раз**, чтобы снять отключение). Исходный код: `MainActivity.maybeAutoStartAlert`,
  `Prefs.countMutedOpening`.
- `adb shell am start ... --ez skip_alert true` подавляет его (для тестирования).

## Твики
Вкладка «Твики» в левом меню содержит небольшие изменения, требующие прав пользователя shell. Они вносятся через loopback-отладку
автомобиля (`AdbLoopback`), тем же путём, которым запускается помощник, поэтому им нужен «Канал данных автомобиля». Каждый твик —
это карточка с переключателем или кнопкой; кнопка **Подробнее** открывает лист, который объясняет, как работает каждый из них, и
перечисляет точные команды. Карточка «Соединение» справа показывает, работает ли и проверено ли сотовое интернет-соединение (и
роуминг) и какая сеть используется приложениями прямо сейчас (`NetStatus`; она читает состояние подключений Android и требует
разрешения `ACCESS_NETWORK_STATE`). При включённом «Канале данных автомобиля» та же карточка показывает ещё и мобильную сеть (LTE,
3G, 2G или нет сигнала) и состояние двух мобильных соединений автомобиля: APN2 (интернет) и APN3 (BYD), с исходными значениями
под ними. Помощник читает их из системных свойств `net.lte.apn2.real_state`, `net.lte.apn3.real_state`, `gsm.network.type` и
`gsm.sim.state` (запрос `net`, протокол помощника v5) каждые 30 секунд, и строка записывается в журнал
(`modem: apn2=... apn3=... net=... sim=...`) всякий раз, когда одно из них меняется, так что настоящий сбой оставляет после
себя точные значения. Исходный код: `TweaksPage` (экран) и `Tweaks` (действия).

**Роуминг данных**: переключатель выполняет `settings put global data_roaming 1` или `0`. **Держать роуминг данных включённым**
(по умолчанию выключено) снова выполняет команду «включить» при запуске приложения, сразу после запуска помощника и в течение
минуты, если настройка оказалась выключенной (настройка читается без особых прав; команда выполняется, только когда значение
не равно 1, не чаще раза в минуту, а после сбоя — через 30 с). Выключение роуминга выключает и этот параметр, иначе он
включил бы роуминг обратно в течение минуты. Обратите внимание: инженерный экран самого автомобиля показывает его внутренний
флаг для apn2, который может читаться как «disconnected», пока соединение работает.

**Подключение к облаку BYD** выполняет `service call cloudmanager 1 i32 4`, что просит облачную службу автомобиля подключиться к
серверу BYD по любой доступной сети, независимо от того, работает ли собственное мобильное соединение автомобиля (APN3), чтобы
телефонное приложение BYD могло связаться с автомобилем. Оно выполняется только когда вы нажимаете кнопку.

**AVAS (внешний звук электромобиля)**: автомобиль включает этот переключатель обратно при каждом запуске, и переключатель в
центре управления — единственный способ его выключить. **Выключить сейчас** ставит тот же переключатель в положение «выкл.» через
API автомобиля BYD (`BYDAutoEngineDevice.setEngineVoiceSimulatorState(0)`), выполняемый небольшим одноразовым процессом
(`AvasTool`) от имени пользователя shell. **Держать AVAS выключенным** (по умолчанию выключено) делает это при запуске
приложения и при каждом включении зажигания и продолжает проверять в течение 90 секунд, потому что автомобиль может включить
его снова вскоре после запуска. В остальное время оно не трогает переключатель, так что включённый вами звук остаётся
включённым до следующего запуска. AVAS — это предупредительный звук автомобиля для пешеходов, который требуется в некоторых
регионах: проверьте местные правила, прежде чем держать его выключенным.

**Перезагрузка модема**: полная перезагрузка модема командами AT, на случай если мобильное соединение автомобиля зависло. После
подтверждения она отправляет модему `AT+CFUN=1,1` (полная функциональность, сначала сброс) — ту же команду отправляет AT Command
Tool инженерного режима. Она идёт через телефонную службу (`service call phoneEx 45`, `invokeOemRilRequestRawBySlot` для слота
SIM 0), которой разрешено пользоваться пользователю shell. Мобильное соединение пропадает примерно на минуту. Затем у модема
запрашивается его собственная регистрация в LTE (`AT+CEREG?`, раз в секунду до минуты), поэтому строка под кнопкой говорит
**LTE вернулся через N с** или **LTE так и не появился: перезагрузите снова**: после перезагрузки модем иногда сначала
регистрируется в 2G, где эта SIM-карта не получает данных, и вторая перезагрузка это исправляет.

**Перезагружать автоматически** (по умолчанию выключено) запускает эту перезагрузку сама, когда оба мобильных соединения
(APN2 и APN3 автомобиля, читаемые из `net.lte.apn2.real_state` и `net.lte.apn3.real_state`) не работают, а у модема нет типа
сети при загруженной SIM-карте, около 2.5 минут подряд. Она использует те же 30-секундные показания, перезагружает не более
3 раз подряд, не чаще чем раз в 15 минут, и начинает счёт заново, когда соединение вернулось. Всё неясное (свойства
прочитать нельзя, SIM-карта ещё загружается) считается «не завис».

**Камеры слепых зон** (по умолчанию выключены): пока включён указатель поворота, камера с этой стороны показывается в окне
поверх других приложений, рядом с собственным окном слепой зоны автомобиля («Triggered by Turn Signal» приложения Image), и
остаётся ещё две секунды после выключения сигнала, как у автомобиля; касание закрывает окно. **Изображение** выбирает
**Вид сбоку** — собственный вид автомобиля сбоку, восстановленный по калибровке его камеры (земля рядом с автомобилем и
впереди, борт автомобиля вдоль одного края), или **Рыбий глаз** — картинку камеры как есть; **Рыбий глаз на стоянке** показывает
«рыбий глаз», когда автомобиль в положении P (передача приходит в ответе помощника об указателе поворота), что бы ни было
выбрано в «Изображении». **На приборной панели** отправляет изображение левого указателя на приборную панель вместо
центрального экрана (изображение правого остаётся на центральном экране); без него оба идут на центральный экран. Приборная
панель показывает лишь один небольшой прямоугольник своего дисплея (область, которую использует собственное окно
автомобиля), поэтому изображение там занимает правую треть этого прямоугольника рядом с окном автомобиля (собственное окно
автомобиля есть только на передаче D и когда его настройка «Triggered by Turn Signal» помещает окно левого сигнала на
приборную панель; приложение читает это из приложения Image, только для чтения; на P, R или N, или когда эта настройка выключена
либо помещает окно только на центральный экран, наше изображение занимает весь прямоугольник). Когда автомобиль настроен на
полноэкранное изображение, наше окно не появляется на центральном экране на D при скорости 15 км/ч и ниже, где автомобиль
уже показывает ту же картинку. Окно называется **Left Front** или **Right Front** и имеет скруглённые углы, как собственные окна
автомобиля. Для окна нужны два разрешения, которые карточка запрашивает в одном месте: она показывает **Нужно разрешение** с
кнопкой **Разрешить**, которая выдаёт приложению доступ к камере и право рисовать поверх других приложений
(`pm grant ... CAMERA`, `appops set ... SYSTEM_ALERT_WINDOW allow` через loopback-отладку, как и другие твики). Указатель поворота
читается через помощника (автомобиль отказывает обычному приложению; он читается так, как читает собственное окно автомобиля,
из выхода ламп `LIGHT_TURN_SIGNAL_LIGHT`, который остаётся включённым, пока лампы используются, включая три мигания при лёгком
касании рычага, а положение рычага служит вторым источником; запрос `turn`, протокол помощника v8), поэтому карточке нужен
«Канал данных автомобиля», как и параметру для приборной панели, где помощник дополнительно записывает флаг автомобиля «показать
изображение головного устройства на приборной панели» (`PANORAMA_SCREEN_PROJECTION_STATUS_IVI_TO_INS_SET`, запрос `proj 1`,
пока окно открыто, и `proj 2` после): это единственное, что помощник записывает. Изображение — это 360-градусный видеопоток
камер автомобиля, открытый через его собственный класс камеры (`android.hardware.AVMCamera`, только разрешение CAMERA) и
отрисованный средствами OpenGL с частотой камеры 30 кадров в секунду; камера открыта только пока открыто окно. Исследование, на
котором всё это основано (видеопоток камер, собственная калибровка автомобиля, почему движок не может обслуживать два окна,
окно на приборной панели), записано в [docs/byd-internals](docs/byd-internals/README.md). Исходный код: `BlindSpot` (указатель
поворота, окна), `SideCamera` (камера и отрисовка), `HelperLink` (соединение с помощником для указателя поворота и флага),
`Tweaks.allowBlindSpot`.

## Обновления
**Настройки > Обновления > Проверить обновления** спрашивает у GitHub самый новый релиз канала, за которым вы следите. Это только
вручную: приложение само никогда не проверяет. Если доступна другая сборка, оно предлагает её установить, показывая список того,
что изменилось в сборках после установленной (он берётся из заметок релизов); приложение загружает APK, сверяет его размер и
SHA-256 с контрольной суммой GitHub, проверяет, что это именно это приложение и что оно подписано тем же ключом, что и
установленное, сохраняет резервную копию поездок, а затем заменяет само себя через loopback-отладку автомобиля и запускается
снова. Поэтому для установки нужен включённый **Канал данных автомобиля** и стоящий автомобиль. BYD сбрасывает свой
переключатель автозапуска при каждой установке, поэтому после неё выполните те же два шага, что и после любого обновления
(Установка / обновление). Загруженный файл остаётся в `Android/data/org.triprecorderng/files/update`. Файл передаётся в
установщик потоком (`cat file | pm install -r --user 0 -S size`, как это делает `adb install`, только для основного
пользователя, после чего копия приложения во втором пользователе удаляется): передача `pm install` пути к файлу на проверенном
устройстве заканчивалась ошибкой «Failed to load asset path from fd», потому что система не могла прочитать файл в общем
хранилище. Замена приложения обрывает отладочное соединение, в котором выполняется команда, и оболочка уходит вместе с ним,
поэтому установка и перезапуск выполняются отдельно (`nohup`, вывод в `/data/local/tmp/triprecng-update.out`), а сама команда
только ждёт, пока этот файл не сообщит о завершении; отказ в установке считывается из него.
- **Каналы.** Релизы называются `stable-N` и `dev-N` (dev-сборки — предварительные релизы); `N` растёт по обоим вместе.
  Название установленной сборки — её название версии (`dev-9`; сборка, сделанная на компьютере, называется просто `0.1`).
  **Настройки > Дополнительно > Канал обновлений** выбирает, за каким каналом следит проверка; выбор другого канала сразу
  предлагает его самую новую сборку — так переключаются между stable и dev в любую сторону.
- **Почему код версии всегда 1.** Android не даёт установить версию с меньшим кодом поверх версии с большим, из-за чего возврат
  с dev на stable был бы невозможен без удаления. При одном коде версии любая сборка, подписанная ключом проекта, ставится поверх
  любой другой. Цена: в информации о приложении Android показывается название версии, а не число.
- **Возврат с dev на stable** сохраняет поездки. База данных только расширяется (новые таблицы или столбцы), и более старая
  сборка открывает более новую базу как есть (`TripDb.onDowngrade`), но гарантировать это для каждого будущего изменения dev
  нельзя: подстраховка — резервная копия в `Documents/TripRecorderNG/backup` (записывается перед каждой установкой).
- Исходный код: `Updates` (проверка, загрузка, проверка подлинности, установка), `MainActivity` (строки и диалоги «Настроек»).

## Языки (английский, арабский и русский)
**Настройки > Язык** выбирает «Автоматически» (как язык головного устройства; арабский или русский только когда таков язык
устройства, иначе английский), «English», «العربية» или «Русский». Выбор хранится как `lang` (`auto|en|ar|ru`) в настройках
приложения, и при его смене приложение перестраивает свои экраны. Числа всегда записываются латинскими цифрами (как на
собственных экранах автомобиля), а в датах на арабском используются арабские названия месяцев и дней, на русском — русские.
Русский читается слева направо, как английский; направление раскладки меняет только арабский.
- **Где используется RTL.** Строка заголовка и левое меню остаются слева в обоих языках (так до них удобнее дотянуться с места
  водителя). Справа налево в арабском только область содержимого: карточки, строки, кнопки, списки и текст. Графики, карта
  маршрута и кольцо рисуются вручную и сохраняют оси времени и чисел слева направо. Диалоги в арабском — справа налево.
  Пути к файлам и числа со знаком остаются слева направо внутри арабского текста (`L.ltr`). Код: `L` (поиск перевода),
  `Ui.contentDirection`, `Ui.show` (диалоги), `MainActivity` (корневая раскладка принудительно LTR, представление `content`
  получает направление содержимого).
- **Как переводится текст.** Каждая видимая строка проходит через `L.t("English text")` или `L.f("English %s", args)`;
  английский текст — это ключ в `assets/ar.tsv` и `assets/ru.tsv` (`english<TAB>translation`, экранирование `\n`, `\t` и `\\`).
  Отсутствующая запись показывает английский текст, поэтому забытая строка видна, но никогда не приводит к сбою. Сохраняйте
  одинаковые заполнители `%s`/`%d` в обоих столбцах (форма `%1$d`, когда порядок меняется).
- **Добавление или изменение текста.** Оберните строку в `L.t`, затем добавьте пару в `assets/ar.tsv` и `assets/ru.tsv` (или
  запустите `python3 tools/check_translations.py`, который перечисляет тексты, отсутствующие в файле, записи, которые больше не
  используются, различия в заполнителях и строки интерфейса, которые не были обёрнуты). Арабский текст написан простым
  литературным арабским и ещё не проверялся носителем языка; русский — так же. Правьте `ar.tsv` или `ru.tsv` напрямую, чтобы его
  улучшить, менять код не нужно.
- Название приложения «Trip Recorder NG» никогда не переводится: строка заголовка, уведомление и название на значке запуска
  одинаковы во всех языках.

## Сборка
`./build.sh` собирает `TripRecorderNG.apk` обычными инструментами Android SDK (без Gradle). Нужны JDK 21 и Android SDK с
платформой (android-34 или новее) и build-tools 35 или новее (d8 из build-tools 34 падает на файлах классов JDK 21). Скрипт
ищет их в местах установки Homebrew; задайте `JAVA_HOME` и `ANDROID_SDK_ROOT`, если у вас они в другом месте. `VERSION_NAME`
задаёт название версии (по умолчанию `0.1`); код версии всегда 1 (см. «Обновления»).

**Ключ подписи.** APK подписывается ключом `triprec.keystore` (алиас `triprec`). Если файла нет, скрипт создаёт новый ключ со
случайным паролем, который хранится в `triprec.keystore.pass`. Оба файла исключены из git и не должны публиковаться никогда.
Сохраните их и сделайте резервную копию: обновление устанавливается только поверх более ранней сборки, подписанной тем же
ключом, поэтому с новым ключом сначала нужно удалить приложение (папка резервных копий сохранит ваши поездки). Чтобы
использовать существующее хранилище ключей, задайте `KEYSTORE=path` и `KS_PASS=password`.

**Переводы.** `python3 tools/check_translations.py` сверяет `assets/ar.tsv` и `assets/ru.tsv` с кодом (см. «Языки»).

## Установка / обновление
`adb install -r --user 0 TripRecorderNG.apk`, затем разрешите доступ к местоположению (или примите запрос на экране).

**Используйте `--user 0`.** В головном устройстве есть второй пользователь Android (999, второй дисплей). Обычный
`adb install -r` ставит приложение и туда, где оно только получает события загрузки и ничего не делает. `--user 0` оставляет
его в основном пользователе. Чтобы удалить копию, которая уже есть в пользователе 999:
`adb shell pm uninstall --user 999 org.triprecorderng`. Обновление из самого приложения делает и то и другое.

**Каждая установка или обновление сбрасывает переключатель запуска BYD для приложения в «disabled»**, что не даёт регистратору
запускаться самостоятельно после перезагрузки. После каждой установки: в настройках автомобиля Setting > BYD auto-start apps
(«Disable background Apps») выключите переключатель **Trip Recorder NG** (выключено = запуск разрешён), затем один раз
перезагрузите головное устройство. Экран «Настройки» самого приложения показывает, запустила ли его последняя перезагрузка
автоматически, а «Эта поездка» предупреждает, когда нет.

## Тестовый хук
`adb shell am start -n org.triprecorderng/.MainActivity --ez demo_trips true` добавляет 7 примерных поездок (одна из них
гибридная) и 2 сессии зарядки; `--ez clear_demo true` их удаляет.

## Канал данных автомобиля (необязателен, по умолчанию ВЫКЛ.)
Включается переключателем Настройки > Канал данных автомобиля. Когда он включён, приложение просит собственную сетевую отладку
автомобиля (ADB, на 127.0.0.1) запустить небольшой процесс-помощник от имени пользователя shell (`Helper`). Помощник может
вызывать API автомобиля BYD и передаёт приложению зажигание, заряд батареи в %, счётчик энергии и одометр через loopback-сокет,
защищённый случайным токеном. Тогда поездки получают расход батареи, расход энергии и изменение одометра.

- При первом открытии приложения после установки или обновления с выключенным каналом оно спрашивает, включить ли его, с тем же
  объяснением, что и у переключателя (**Включить** или **Не сейчас**, что оставляет его выключенным). Снова оно спрашивает только
  через неделю, если канал всё ещё выключен, и никогда не при каждом открытии, и скорость не учитывает. Переключатель в
  «Настройках» остаётся местом, где это меняется.
- Первое включение: на некоторых головных устройствах показывается «Allow debugging?» для этого приложения (отметьте
  **Always allow**, нажмите Allow). На проверенном устройстве автомобиль принял ключ приложения через loopback автоматически, без
  запроса.
- После этого помощник перезапускается автоматически при каждой загрузке, пока переключатель включён.
- Обработка соединения: приложение повторяет попытки с нарастающей задержкой (3, 5, 8, 13, 20, 30, 45, 60 с), нажатие «Включить»
  или «Переподключить» / «Повторить сейчас» никогда не теряется (оно ставится в очередь, если попытка уже идёт), регистратор
  каждые 3 с проверяет наличие помощника, пока канал нужен, а строка состояния в «Настройках» отражает то, что реально
  подключено («Подключено — помощник работает», «Подключение...», «Нет связи — ... (повтор через N с)»). Типичные времена:
  ~6 с от включения до данных, ~10–14 с на восстановление после остановки помощника. Поездка не начинается в режиме «только
  GPS», пока помощник ещё подключается (задержка 25 с), поэтому при включённом канале используется начало по зажиганию.
- Выключение останавливает помощника и повторные попытки (снова только GPS). **Забыть** (Настройки > Ключ отладки) удаляет ключ
  приложения. То, что автомобиль мог сохранить у себя (если сохранял), вне досягаемости приложения; «Revoke debugging
  authorizations» в параметрах разработчика автомобиля, если такой пункт есть, это очищает.
- Исходный код: `AdbKey`, `AdbLoopback`, `Helper`, `HelperVehicle`, `HelperLauncher`, `Prefs`.

## Проверено на головном устройстве (DiLink 5.1, 2026-10-04)
- Канал данных автомобиля: включён из «Настроек», помощник запущен через loopback ADB, `bind: ok`, регистратор переключился на
  «BYD API via helper»: читаются зажигание (уровень питания 2), заряд батареи в %, счётчик энергии и одометр; поездки идут в
  режиме по зажиганию. Выключение останавливает помощника; «Забыть» удаляет ключ; оба работают.
- Автомобиль принял совершенно новый ключ приложения через loopback **без всякого запроса** (значит, любое приложение на этом
  устройстве может запускать команды shell через loopback ADB; это свойство автомобиля, а не этого приложения).
- Если помощника остановить, работающее приложение перезапускает его в течение нескольких секунд. Служба регистратора
  продолжает работать при закрытом экране.
- **Запуск после перезагрузки зависит от переключателя BYD для каждого приложения.** Изменённый Android от BYD пропускает
  манифестные широковещательные сообщения (BOOT_COMPLETED и пользовательские) стороннему приложению, процесс которого не
  запущен, когда стартовое значение BYD для него говорит «disabled» (`BroadcastQueue: skip reciever ... ignored !!!`; при
  выключенном переключателе в журнале вместо этого `UID ... is running now` и `boot receiver: ...`). Это значение нельзя
  прочитать или изменить из shell; оно сбрасывается в «disabled» при каждой установке или обновлении. Переключатель — это запись
  Trip Recorder NG в Setting > BYD auto-start apps («Disable background Apps»): выключено = разрешено. У головного устройства
  есть и второй пользователь Android (999, второй дисплей), который тоже получает события загрузки; приложение их игнорирует и
  работает только в основном пользователе.
- Однократное открытие приложения запускает службу (и помощника, если канал включён), пока переключатель ещё включён.
- Настоящие поездки записывались с GPS-маршрутами и, при включённом канале, с зарядом батареи и энергией по каждой поездке
  (например, одна поездка в 186 км, с 99 % до 27 %, 22.9 кВт·ч).
- Не подтверждено: автозапуск после настоящей перезагрузки головного устройства при выключенном переключателе BYD для самой
  новой установки.
